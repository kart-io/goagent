# 业务接入与故障恢复验收

本页用于把执行内核的契约测试转成宿主业务的验收条件。现有退款案例使用合成订单、演示审核人和 SQLite 效果账本；Postgres 集成验证实际数据库的持久化与租约，不代表支付、身份系统或生产业务已经接入。

## 本地可重复验证

将 goagent、goagent-harness、goagent-examples、goagent-contrib 放在同一父目录，在 goagent 执行：

```sh
make test-contracts
make test-frameworkbench
make compatibility COMPAT_OUT=/tmp/goagent-acceptance-new
```

`COMPAT_OUT` 必须不存在。验证器使用临时 modfile 将所有本地模块绑定到当前源码，关闭外部 go.work；不改写下游依赖文件。核对 `summary.json` 中的 `core_directory`、`core_revision` 和各模块 `status`，再逐项检查 `skipped_tests`。

需要 Postgres 实库验证时，在专用测试数据库上配置 `GOAGENT_PGSTORE_DSN` 后执行同一命令，使用另一个新报告目录。相关测试创建隔离 schema 并在结束后删除；需具有建 schema 权限。连接串通过环境提供，不写进报告或提交文件。必须确认 pgstore 与 Harness 的 postgres 集成模块实际执行了测试，不能以它们的编译成功或跳过结果代替实库通过。

如果该数据库由本次创建的独立 Docker 容器提供，可再设置 `GOAGENT_PGSTORE_CONTAINER` 为容器名，执行数据库重启和同步提交配置验证。这两项会重启容器、修改服务器配置，只对独立测试容器启用。

重启验证需显式固定宿主端口（如 `-p 127.0.0.1:55432:5432`）。使用随机发布端口时，Docker 重启后可能分配新端口，旧 DSN 的连接拒绝属于环境配置错误；应保留失败记录，修正端口后重新验证。

退款案例的跨进程测试位于 goagent-examples 的 `workflow/refund-recovery`。跨仓命令会执行该包；原始日志中保留审批拒绝、进程退出后恢复和重复恢复的断言结果。需单独运行时，在正确绑定当前源码的工作区执行：

```sh
GO_TEST_MODE=true go test -race -count=1 -timeout=120s ./workflow/refund-recovery
```

单独运行后须确认 `go list -m -json github.com/kart-io/goagent` 的替换目录，防止验证到了已发布的旧版本。

## 真实业务接入所需输入

宿主提供测试服务地址及协议、认证方式、租户和可操作的订单/工单范围、允许的写入操作、预期结果，以及效果查询接口。凭据通过环境或宿主密钥系统提供，测试资料中只记录身份角色与测试数据标识。

业务写入需提供稳定业务请求 ID。跨执行 ID 重试同一业务时仍复用该 ID；模型生成的工具调用 ID 不能替代业务去重约束。存在远程支付等不可回滚效果时，由业务端提供幂等与回执查询/对账协议，不能把远程请求塞进本地事务就视为原子提交。

## 验收矩阵

| 场景 | 必须验证的结果 | 业务证据 |
|---|---|---|
| 未登录、无权限、跨租户 | 宿主在审批/新效果前拒绝；审批键不能充当身份凭证 | 已认证身份与权限判定、业务写入数为零 |
| 正常申请与审批 | 审批绑定原始订单、金额和审核版本，完成后能查询效果 | 审核记录、状态变更、业务回执 |
| 重复请求、不同执行 ID 重试 | 同一业务 ID 只有一笔效果，返回同一回执 | 唯一约束、业务系统按请求 ID 查询结果 |
| 同 ID 改参数 | 订单、金额或租户变化时拒绝，不覆盖原申请 | 原始申请与拒绝结果 |
| 写入提交后、检查点保存前崩溃 | 新进程先查回执或使用服务端幂等键，完成恢复且不重复写入 | 进程退出证据、恢复轨迹、业务回执与写入数 |
| 审批后事实变化或授权撤回 | 新效果前再次校验；拒绝过期审批、订单版本变化和已撤销权限 | 版本、期限、权限更新与拒绝结果 |
| 并发不同请求 | 跨请求累计约束仍有效，不因只锁请求 ID 而超额 | 并发记录、数据库约束与累计结果 |
| 取消、模型断流、未知用量 | 无成功终态；预算与未知效果可诊断，恢复不清零 | 终态、预算账本、诊断结果 |
| 升级恢复 | 旧运行按原版本续跑，或明确拒绝；不静默套用新状态/函数结构 | 升级前检查点、新版本拒绝或迁移验证 |
| 数据库持有者退出与租约接管 | 新实例可接管，旧持有者失效后不能再写 | 真实数据库测试、连接间观察与 fencing 拒绝 |

本地合成案例已验证的项目和真实业务环境的项目分别记录。单元测试的事务替身不能证明实库并发性，合成模型通过率不能证明真实业务效果；观察事件也不能替代业务账本。

## 验收记录

保存源码提交、工具链、模块依赖定位、测试数据来源、逐场景结果与跳过项。失败和取消保留在结果中，不在同一目录覆盖或删除。原始日志留在访问受控的报告目录，进入仓库的结果不包含凭据、真实个人信息或完整连接串。
