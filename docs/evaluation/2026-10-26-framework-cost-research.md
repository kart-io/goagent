# 其他 Agent 项目的成本控制调研

调研日期：2026-10-26。目标是减少 GoAgent 完成同一任务的模型请求和上下文输入；能力比较与性能评测分开。外部资料为官方文档/源码，网页及主分支会继续变化。

## 已核对的机制与取舍

| 项目 | 机制 | 对当前项目的意义 | 代价/限制 |
|---|---|---|---|
| OpenAI Agents SDK | `tool_use_behavior` 支持直接使用工具输出，或按工具名停止 | 终态查询可省掉最后一次模型总结 | 应用必须确认结果已经完整、可展示 |
| LangChain | `ClearToolUsesEdit` 达到阈值后清除较早工具输出，保留近期结果并可排除工具 | 适合多轮、大工具结果；不需要新增摘要调用 | 旧证据被移除后，可能需要重新查询；Token 计数可采用近似值 |
| Google ADK | 按间隔或阈值压缩事件，配置重叠窗口和摘要模型 | 适合长会话减少反复发送历史 | 摘要会增加模型调用，需要核算后续节省和信息丢失 |

来源及用途：

- [OpenAI Agents SDK：Tool use behavior](https://openai.github.io/openai-agents-python/agents/#tool-use-behavior)：确认默认再调用模型、按工具名结束等语义。
- [LangChain：Context editing 源码](https://github.com/langchain-ai/langchain/blob/master/libs/langchain_v1/langchain/agents/middleware/context_editing.py)：核对阈值、近期保留、排除名单、占位符和工具调用关联处理。它不等同于模型摘要。
- [Google ADK：Context compression](https://adk.dev/context/compaction/)：核对间隔、重叠范围及 LLM 摘要器配置。

## 本轮落地

新增 Builder `WithReturnDirectTools("order_status")`，只影响支持 `llm.ToolStreamClient` 的 `ExecuteStream/AsRunnable`。默认不启用，旧 `Execute/ExecuteWithTools` 不使用这个策略。

本轮恰好一个工具调用命中名单，且工具成功返回完整结果时直接结束。字符串原样返回，其他值 JSON 编码；空结果、工具失败、编码错误或取消均失败。工具返回完整答案所需的权限、数据范围和格式仍由工具实现负责，模型不会再执行润色、引用补充或格式转换。

多工具调用继续走原生模型循环，避免把某一个结果当成全部答案。最后一次模型请求可以调用直接返回工具，因为不再需要后续模型请求；多工具/未命中名单的情况仍须预留最终回答额度。错误不会触发隐藏重试或追加总结请求。

复用现有完成处理：记忆、状态、检查点、中间件、回调和用量汇总。元数据新增 `answer_source=tool`、`return_direct_tool`；`model_calls` 仍为实际调用次数，缺失 usage 仍记为未知。`answer_usage_reported=false` 表示最终答案来自工具，无独立答案模型用量，选择工具那一轮的真实用量仍计入总量。

消费者以 `done.Output` 为最终答案；之前的 `text` 仍可能包含模型调用工具前的临时说明。

## 后续顺序

1. 大工具结果：先按业务字段投影/分页，保留原始结果引用，再评估历史工具输出清理；不默认截断 JSON 或删除证据。
2. 长对话：先采集每轮输入量、摘要成本和任务成功率，再决定触发阈值、保留最近几轮及摘要模型。当前短题集不能证明摘要方案节省成本。
3. 工具很多时：按已知业务路由提供工具子集；若用额外模型选工具，要同时计算选择调用的成本和漏选率。
4. 答案缓存：需要明确租户、用户权限、资料版本、有效期和副作用边界后再启用。不能只按问题文本缓存业务查询。

这些是针对当前代码的工程判断，不表示外部项目在所有场景中更快或更便宜。

## 验证边界

离线测试比较默认两请求和直接返回一请求，覆盖多工具回退、最后一轮预算、状态失败/错误/空值/取消/编码失败、真实用量和记忆。评测包通过实际 SDK 接假 HTTP 服务，验证单次请求完成终态工具任务。

在线终态工具题集与之前的推理题集分开。题集的工具是提供完整状态文本的业务查询，预期答案与完整文本一致；不把资料检索结果冒充推理答案。线上报告及统计见[评测说明](README.md)。
