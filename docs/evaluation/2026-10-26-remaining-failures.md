# 剩余失败修复与执行策略验证

日期：2026-10-26。继续处理[大样本复测](2026-10-26-scale-validation.md)中 GoAgent 默认流程的 8 次失败。旧报告保留，评分不变，所有请求仍计量。

## 原因与修复

1. 评测应用的系统提示同时要求“证据不足时 UNKNOWN”及完成原样返回任务，边界状态文本容易被模型误认为没有证据。共用应用提示改为区分原样返回与事实推理；不读取 `answer` 标签，不覆盖业务调用方自己的系统提示。
2. 已取得工具结果却只剩一次模型额度时，仍提供普通查询工具，会让模型再次查询但无法生成最终答案。Builder 原生工具循环现在在最后一轮只保留显式配置的终态直返工具；未配置时不提供工具，把额度用于回答。首轮直返、有充足额度的连续工具调用保持原行为；非法的额外工具调用仍报错，不执行副作用，不追加模型请求。
3. 模型仍可能改写状态原文，所以对有严格原样输出契约的业务任务，使用现有 `WithReturnDirectTools` 执行，不再让模型重新生成这段文本。事实推理任务仍保留模型回答，不能无条件把所有工具输出直返。

第 1 项属于评测应用提示，第 2 项属于框架行为，第 3 项属于应用执行策略。没有把模式切换后的成绩伪装成默认流程成绩，也没有使用正则覆盖模型答案或按失败结果事后更换答案。

## 按业务契约选择执行模式

新增 `cmd/stress -mode contract`。它依据早已存在的 `direct_eligible` 任务元数据选择：80 道原样输出题使用直返，40 道推理/无工具题使用默认循环。每题只执行一次，不先尝试默认流程再隐藏失败；不读取评分标签。相关单测将所有答案标签替换成同一任意字符串，验证路由仍完全相同。

生产应用需要由明确的业务操作类型配置 `WithReturnDirectTools("工具名")`，不能仅靠问题关键词猜测是否可以跳过推理。该模式的通过率属于应用策略，不等于默认模型总结流程的通过率。

复现（从 `evaluation/agentbench` 运行；结果目录不能已存在）：

```sh
OPENAI_API_KEY="$DEEPSEEK_API_KEY" OPENAI_BASE_URL=https://api.deepseek.com \
OPENAI_MODEL=deepseek-flash go run ./cmd/stress -live \
  -mode contract -count 120 -seed 20261026 \
  -workers 4 -out /tmp/goagent-contract-suite
```

第二组使用种子 `20261027`，题目 ID 和多数参数不同，生成模板仍相同。这是模板内的新样本验证，不是生产独立题集，也不构成永不失败的保证。仍未覆盖真实工具参数抽取、权限、写操作幂等与持久化恢复。

原种子按契约执行结果：**120/120 通过**，其中此前 8 个失败 ID 全部通过；模型请求 150 次、总 Token 59249，usage 完整。相较上轮默认组 230 请求减少约 34.8%。这是显式更换执行策略后的成绩，原默认组失败记录未修改。
