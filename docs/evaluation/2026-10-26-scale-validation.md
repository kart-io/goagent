# 大规模功能验证

日期：2026-10-26。范围为 Builder 原生工具循环、工具结果直返、OpenAI 兼容 SDK 传输。这里的成功率不代表整个框架已通过生产验收。

## 数据与验收

- 离线执行矩阵：20 类路径 × 80 组内容、分片与调用 ID 组合，共 1,600 组。覆盖正常直返、结构化结果、默认循环、多工具、名单外工具、无用量、直接回答，以及错误参数、重复/缺失 ID、未知工具、失败状态、空结果、截断、上游失败、取消、输出长度上限、预算和空工具响应。
- 离线 SDK：固定种子 1,200 条生成记录中的 800 条终态工具题，经过本项目实际 SDK 接本地假模型，共 800 次协议验证。另有 40 次并发执行隔离检查。这些结果只能证明被覆盖的协议与逻辑行为，不能作为真实模型质量成绩。
- 在线：固定种子 `20261026`，120 个不同题目 ID，12 类各 10 题。当前历史报告保留 GoAgent 首轮 200 次执行（80 道终态题各测默认/直返，40 道其他题测默认）及修复后的 120 次默认执行，共 320 条记录。清理标记写在报告中，数据未重新跑过模型。

类别：中文订单、英文退款、多行文本、JSON 文本、Unicode、转义字符、长结果、状态边界、证据筛选、证据计算、无证据拒答、无工具算术。固定模板内记录有相关性，不能将生成数当成生产样本独立性，也不据此计算泛化置信度。

答案去除输出首尾空白后严格匹配，保留换行、引号和转义差异；有工具证据时必须实际执行工具。调用契约另外要求工具恰好一次，默认工具题两次模型请求、直返/无工具题一次。错误、截断、没调工具、错误答案均失败，失败的请求及 Token 仍计入总量。未知 usage 单独报告。没有使用额外模型打分。

模型为 `deepseek-flash`，温度 0.2，每任务最多 2 次模型请求，每次输出上限 512 Token，已观测用量阈值 8000，45 秒超时，并发 4。按题轮换组别顺序；未禁用服务端缓存。延迟受并发与本机负载影响，不用于框架速度排名。

保留的两轮 GoAgent 记录合计实际访问模型上游 540 次，供应商报告 222115 Token。包括所有失败，不估算未提供单价的金额；本地预算代理拦截的额外请求不计作供应商调用。

## 首轮发现

| 框架/配置 | 答案及调用契约通过 | 请求数 | 总 Token |
|---|---:|---:|---:|
| GoAgent 默认 | 75/120 | 230 | 97188 |
| GoAgent 直返 | 80/80 | 80 | 30270 |

首轮 GoAgent 的 45 次失败全部保留。保留的 200 次执行都有完整 usage。直接/默认组题数不同，不能直接比较此表的 Token 总量作为节省比例。

主要发现：原生循环把字符串工具正文再次 JSON 编码，导致额外引号和转义进入模型上下文。25 次失败可仅通过一次 JSON 解码还原为正确答案；还有转义改写、文本差异和截断失败。没有因此修改评分规则。

已修复：原生循环字符串正文直接传递，结构化值继续 JSON 编码。增加了对换行、反斜线、引号和 Unicode 正文原样续接的断言。字符串 `"null"` 仍是合法结果，与真实 nil 区分。

## 修复后的结果

本项目的 120 次默认组复测完成；题集 SHA256、模型、温度和预算与首轮一致。没有只重跑成功概率高的样本，也没有增加重试额度。

| 框架 | 默认组总通过 | 终态工具原样输出 | 推理/无工具 | 请求数 | 总 Token |
|---|---:|---:|---:|---:|---:|
| GoAgent | 112/120（93.3%） | 72/80 | 40/40 | 230 | 94657 |

所有 120 次复测均有完整 usage。剩余 8 次失败未删除；程序按验收规则返回非零退出码，表示评测全部完成但没有全通过，不是测试程序中途退出。

GoAgent 的 8 次剩余失败：5 次将 `false`、`null` 或未找到记录的原文改成 `UNKNOWN`，1 次将 JSON 文本改成 `UNKNOWN`，2 次模型继续请求工具而耗尽两次请求预算。最后两次按框架契约失败，没有偷偷追加请求或执行无法形成最终答案的额外工具。


80 道相同终态题上，GoAgent 修复后默认组为 160 请求、69672 Token；首轮直返组为 80 请求、30270 Token，均保留全部成功/失败的用量。观察到请求减少 50%、Token 减少约 56.6%，同时直返组 80/80 通过。两组不是同时运行，模型随机性与缓存会影响 Token；这是适用任务的观测，不能保证所有任务同样节省。

结论：本轮验证支持对结果已可展示的单个终态工具启用显式直返；通用模型总结流程仍存在失败，不能宣布“全部功能已成功”。真实工具参数、生产分布及未覆盖能力仍需单独验收。

## 仍未验证

本轮代码验证已完成：根模块 `GOMAXPROCS=2 GO_TEST_MODE=true go test -p 2 ./... -short -count=1 -timeout 120s` 通过（57 个有测试的包）；Builder 与评测包竞态检查通过，40 次并发检查通过；修改包及评测包 golangci-lint v2.6.2 均为 0 issues。此前高并发全仓链接因本机资源压力主动停止，降低并发后已重跑完成。代码回归通过与线上模型未全通过是两个不同结论。

尚无生产数据；无参数 lookup 工具不能验证真实工具参数提取和选错工具的分布。持久化崩溃恢复、写操作幂等、跨租户权限、长会话累计成本和生产流量延迟不在本轮成绩中。上线门槛需要业务方提供脱敏题集与错误容忍标准。
