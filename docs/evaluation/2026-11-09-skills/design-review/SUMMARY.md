## 确认发现与关闭

| ID | 严重度 | 原问题 | 修复及验收 |
|---|---|---|---|
| DC-01 | P2 | `!!binary /w==` 在 YAML→JSON 转换中被替换为 `�`，随后作为合法元数据接受 | 新 `DecodeMapping` 在转换前拒绝二进制类型；旧 Unmarshal 不变。codec、Parse 回归先失败后通过 |
| EXE-01 | P2 | 正文加载的已知资源枚举限制被归为执行失败，持久 Builder 无法给模型反馈，显式恢复消耗尝试次数 | 全错误树检查之后把已知正文限制映射为 Rejected；未知/混合 I/O、取消及关闭仍为执行错误。真实 Harness 的深度/条目两种限制，经 Dispatcher 和持久 Builder 均完成并可重放，日志保持 completed/1 |
| VAL-01 | P3 | 迁移文档命令在测试失败后可能被清理命令的退出 0 掩盖 | 子 shell、set -euo pipefail、trap；对文档原代码块进行无副作用模拟，测试返回 23 时整体返回 23 |

没有为清理错误的静态疑点修改生产代码：`errors.Is(ErrNotExist)` 对联合错误的判定理论上宽泛，但当前 Go 1.27.3 Root.Close 返回 nil，未证实实际可达组合。报告将其列为可选加固，避免把假设写成确认缺陷。

## 设计是否合理

| 决策 | 判断与依据 |
|---|---|
| `skills` 是顶层可选包，非 core 能力 | 合理。直接依赖只有 codec、errors、constants；执行内核不需理解 SKILL.md，导入门禁通过 |
| 公共 Catalog + 可选工具 + Harness 装配 | 合理。加载与授权、默认目录、提示词、Manifest 分离；没有反向依赖 Harness，也没有另建执行器 |
| 调用方传入 `os.Root`，Catalog 持有独立子根 | 适合首版本地来源。所有权及关闭责任明确；无需为尚不存在的第二种来源引入 Provider/Resolver |
| 发现时缓存正文，资源按需实时读取 | 可接受且已披露。符合面向模型的分层消费；Digest 只覆盖原始 SKILL.md，不等于整包不可变或签名 |
| v3 严格字段校验和原始文档摘要 | 有明确一致性收益，也有真实迁移成本。布尔、null、字符串版本、ASCII 名称及旧 Manifest 差异已有文档 |
| 新严格 YAML 入口复用原转换逻辑 | 合理。两次解析是维护取舍，避免改变其他配置消费者；当前没有证据要求重写共享 codec |
| 持久结果重放 | 符合框架契约。成功和拒绝均固定为原调用结果；新调用才能读取变化后的资源。宿主负责 DurableScope、Manifest 和 Assembly 生命周期 |

平台、句柄容量、Load 资源枚举整体失败，以及锁等待/系统调用的取消边界已补充到公开指南。固定容量、来源优先级和严格失败策略均有文档，不需要立即扩展为复杂配置体系。
