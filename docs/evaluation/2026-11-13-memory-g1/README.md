# 记忆 G1 存储改造：真实模型冒烟对比（2026-11-13）

对应设计 `docs/design/MEMORY_G1_STORAGE.md` 7.5：G1 改造后（记录进 durable state，新近性默认从创建时间起算）与 G0 基线对比召回与作答结果，并比较 `TrackAccess` 开关。

## 设置

- 数据：LoCoMo（`locomo10.json`），按题型分层抽 200 题，1 轮；与基线 `../2026-11-10-memory/` 抽到的题目逐一相同。
- 模型：抽取与作答 deepseek（温度 0），判定 `gpt-4o-2024-08-06`，嵌入 `gemini-embedding-001`，与基线相同。
- 方案：memory、graph。
- 命令：

```bash
go run ./scripts/memeval -format locomo -data locomo10.json -sample 200 -repeats 1 -concurrency 10 \
  -systems memory,graph -chat deepseek -judge openai:gpt-4o-2024-08-06 -embed gemini:gemini-embedding-001 \
  -out locomo-200-default.md -results locomo-200-default.jsonl
# 同上，加 -track-access，输出 locomo-200-track.md / .jsonl
```

基线为 `../2026-11-10-memory/locomo-200x2.jsonl` 的第 1、2 轮。每轮都重新抽取记忆，所以每组结果都含抽取波动。

## 补充：graph 默认第 2 轮

第 1 轮 graph 默认的 temporal 题偏低，补跑 1 轮（只跑 graph，`locomo-200-graph-r2.md` / `.jsonl`）。

| 配置 | 准确率 | 去掉对抗题 | 证据召回 | 对抗 | 多跳 | 开放域 | 单跳 | 时间 |

| G0 第 1 轮 | 54.0% | 43.9% | 85.2% | 40/45 | 7/28 | 4/10 | 34/85 | 23/32 |
| G0 第 2 轮 | 52.0% | 43.2% | 89.0% | 37/45 | 10/28 | 4/10 | 30/85 | 23/32 |

| G1 默认第 2 轮 | 52.5% | 40.0% | 83.9% | 43/45 | 10/28 | 3/10 | 29/85 | 20/32 |
| G1 track-access | 54.0% | 43.2% | 85.8% | 41/45 | 8/28 | 4/10 | 36/85 | 19/32 |

- 总体：G1 默认两轮的题目平均 50.5%，G0 两轮 53.0%；同轮次配对 43 胜 53 负，p = 0.36。
- 时间题：G1 默认两轮对 G0 两轮 4 胜 14 负，p = 0.031（两轮不独立，p 值偏乐观）。G1 三组都低于 G0（16、20、19 对 23、23），track-access 也一样，所以与 `TrackAccess` 无关。
- 证据命中相同（时间题 28～29/32），但 G1 在可回答题上更常答 "not mentioned"：G0 两轮各 57/155，G1 三组 64～69/155；对抗题（应弃答）因此略高。召回到了正确会话的记录，但召回块里的内容不足以作答的情况变多了。

## 结论

- 总体准确率在 G0 的 95% 区间内（memory 40–53%，graph 46–60%），总体配对没有显著差异。
- graph 的时间题与可回答题的弃答率有一致的退化迹象，与 `TrackAccess` 无关，原因可能在 G1 召回路径的其他变化。现有数据只记录了召回的会话，没有记录召回块内容，无法定位；需要在同一份抽取结果上对比 G0 与 G1 的召回块。
- 默认保持 `TrackAccess` 关闭（设计第 8 节的取舍不变）：开启它不能消除这一差距。

逐题结果见同目录的 `*.jsonl`，汇总见 `*.md`。
