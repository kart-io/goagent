# 记忆 G1 存储改造：真实模型冒烟对比（2026-11-13）

对应设计 `docs/design/MEMORY_G1_STORAGE.md` 7.5：G1 改造后（记录进 durable state，新近性默认从创建时间起算）与 G0 基线对比召回与作答结果，并比较 `TrackAccess` 开关。

## 设置

- 数据：LoCoMo（`locomo10.json`），按题型分层抽 200 题，1 轮；与基线 `../2026-11-10-memory/` 抽到的题目逐一相同。
- 模型：抽取与作答 deepseek（温度 0），判定 `gpt-4o-2024-08-06`，嵌入 `gemini-embedding-001`，与基线相同。
- 方案：memory、graph。
- 命令：

```bash
go run ./scripts/memeval -format locomo -data locomo10.json -sample 200 -repeats 1 -concurrency 10 \
  -systems memory,graph -chat deepseek -judge openai:gpt-4o-2024-08-06 -embed gemini:gemini-embedding-001 \
  -out locomo-200-default.md -results locomo-200-default.jsonl
# 同上，加 -track-access，输出 locomo-200-track.md / .jsonl
```

基线为 `../2026-11-10-memory/locomo-200x2.jsonl` 的第 1、2 轮。每轮都重新抽取记忆，所以每组结果都含抽取波动。

## 根因排查：同一份模型输出上对比 G0 与 G1

方法：在模型请求的 HTTP 层录制与回放（本地代理，按请求体哈希缓存响应；`DEEPSEEK_BASE_URL`、`GEMINI_BASE_URL`、`OPENAI_BASE_URL` 指向代理），G0（`a4f09197`）与 G1（`f74d2547`）的 memeval 原样运行，不改代码。作答请求含召回块，据此逐题比较召回块。

1. G0 录制：graph、同样的 200 题，真实模型。
2. G0 回放自己的录制（对照），G1 默认与 G1 `-track-access` 回放同一份录制。回放时不调用模型：未命中的作答与判定返回固定弃答，只用于比较召回块。

| 比较（均为回放，条件相同） | 抽取与整理请求 | 召回块相同 | 召回块不同 |
|---|---|---:|---|
| G1 默认 对 G0 | 2114 条逐字节相同 | 198/200 | 时间题 1 道（内容不同）、对抗题 1 道（仅顺序） |
| G1 track-access 对 G0 | 2114 条逐字节相同 | 199/200 | 对抗题 1 道（仅顺序） |

- 写入路径（抽取、整理、反思、关系）与 G0 逐字节相同；召回的候选、打分与召回块在 200 题中有 198 题相同。
- 唯一内容不同的时间题是 "When did Melanie go to the museum?"：G0 每次召回都更新访问时间，前面题目召回过的记录新近性略高，在相关性接近时排到前面；G1 默认不记录访问（`TrackAccess` 关闭），第 5 条换成了另一条记录。换上的记录更长，4000 字预算用尽，两条关系没有放入。两边都没有包含答案的记录（G0 在这道题上也答错）。开启 `-track-access` 后这道题与 G0 相同。
- 剩下一道对抗题只是顺序不同：G1 的访问记录是异步批量写入，G0 是同步写入，平分时先后不同。

结论：G1 没有在召回路径上丢失可回答的时间信息。真实运行中时间题的差距（G0 11-10 两轮 23/32，G1 三组 16、20、19）来自运行间波动：

- 今天用 G0 代码重新跑同样的 200 题（即上面的录制），总体 103/200（51.5%），时间题 20/32，与 G1 同一水平。
- 模型输出相同时，评测本身也不完全确定：G0 回放自己的录制，2114 条抽取与整理请求中有 76 条与录制时不同（G1 完全相同的 76 条），召回块有 27 题不同。新近性按墙上时钟计算，录制与回放的耗时不同，相关性接近的候选先后会变，之后的整理请求随之不同。

## 固定评测时钟

`memory.Config.Now` 注入时钟，`memory/memeval` 把它固定在每个对话最后一个会话的时间。评测中所有记录的新近性因此相同，召回只按相关性与重要性排序（同分按 ID），不再受评测耗时影响；`-track-access` 随之不起作用，已删除。

验证（`replay-determinism.txt`）：用固定时钟的 memeval 录制一次（graph、同样的 200 题、真实模型；抽取与整理请求与上面 G0 录制相同的直接取录下的响应，新增 8 条），再回放两次：

| 比较 | 与录制不同的请求 | 召回块相同 | 准确率 |
|---|---:|---:|---:|
| 回放 1 对 录制 | 0 / 6731 | 200/200 | 53.0%（同） |
| 回放 2 对 录制 | 0 / 6731 | 200/200 | 53.0%（同） |

固定时钟之前，G0 回放自己的录制有 76 条请求、27 题召回块不同（见上）。录制本身即一次真实运行：graph 53.0%（`locomo-200-graph-fixed-clock.*`），各题型为对抗 42/45、多跳 8/28、开放域 5/10、单跳 31/85、时间 20/32，在 G0 的 95% 区间（46–60%）内。之后同一份模型输出上的对比不再含评测自身的波动。

## 结论

- 总体准确率在 G0 的 95% 区间内（memory 40–53%，graph 46–60%），总体配对没有显著差异。
- G1 与 G0 在同一份模型输出上的召回块 198/200 相同；时间题的差距是运行间波动，不是 G1 的退化，不需要修改召回实现。
- 默认保持 `TrackAccess` 关闭（设计第 8 节的取舍不变）：它只影响相关性接近时的先后。
- 评测的不确定性一部分来自墙上时钟：评测中所有记录在同一小时内写入，新近性（半衰期 7 天）只起平分时的先后作用，却让同一份模型输出的两次运行结果不同。已改为固定评测时钟，同一份模型输出的运行召回完全相同（上一节）。

逐题结果见同目录的 `*.jsonl`，汇总见 `*.md`；今天用 G0 代码重跑的结果为 `locomo-200-graph-g0-rerun.*`，回放比较的输出为 `replay-compare.txt`；固定时钟后的录制结果为 `locomo-200-graph-fixed-clock.*`，确定性检查为 `replay-determinism.txt`。
