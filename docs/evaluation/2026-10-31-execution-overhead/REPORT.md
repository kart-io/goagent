# 离线执行开销实测

日期：2026-10-31。基线a662fae加本轮探针；before为原JSON账本复制，after为类型化深复制及跳过持久读取前无用复制。未改变持久格式、锁和同步Save语义。

## 环境与可复现命令

- Apple M4 Pro，darwin/arm64，Go 1.27.2，14 CPU，GOMAXPROCS=14；模块最低版本仍为Go1.25，本报告没有宣称在Go1.25上测量。
- 两次矩阵及微基准分别串行运行，避免本任务其他测试负载。环境细节及时间戳见原始JSON。
- 原始结果：[矩阵before](matrix-before.json)、[矩阵after](matrix-after.json)、[微基准before](ledger-before.txt)、[微基准after](ledger-after.txt)。

```bash
env -u GOROOT go run ./evaluation/executionbench/cmd/run \
  -operations=10,100,1000 -modes=none,memory,file -timeout=10m > matrix.json
env -u GOROOT go test ./core/budget -run '^$' \
  -bench '^BenchmarkRecordUsageFixedLedger$' -benchmem -benchtime=200ms -count=1
```

本机GOROOT与PATH工具链不一致，因此仅对子进程取消GOROOT；其他机器按正常环境运行即可。

## 方法

三模式共用无副作用Dispatcher工具、固定空参数、每操作不同key和固定合成usage（2输入+1输出）。none无预算，memory内存预算，file只持久预算，不绑定工具日志。调用者带任何Journal都会在初始化前被拒绝，防止污染宿主Store和测成回放。

计时和TotalAlloc只覆盖Reserve、工具调用与RecordUsage循环，排除初始化、最终统计和清理。P50/P95基于成功操作；失败返回部分报告与error。内存分配为该期间进程级TotalAlloc差值；存活堆与goroutine为GC后的进程采样，不是峰值或无泄漏证明。文件数与字节为最终采样，临时子目录在返回前清理。

## 判断与已实施优化

1000操作的内存预算总耗时约1176ms降至81ms，累计分配约701MB降至185MB。固定1000条账本的RecordUsage微基准由515962ns/op、268576B/op、2034allocs/op变为29896ns/op、86768B/op、1007allocs/op。

据此实施了类型化深复制：保留nil未知用量并分别复制usage指针、Estimates和Tools，避免JSON往返与临时字符串；持久读取从零值解码，省掉先复制随后丢弃的内存镜像。固定128条账本资源上限测试在旧实现观察218allocs/op超出192上限，优化后通过；另有全部可变证据隔离及现有恢复/配置漂移回归。

文件模式仍约30ms/操作，时长差异需要重复样本确认，持久同步开销仍占主要成本。当前保留同步保证；应以实际宿主存储与任务规模决定下一阶段优化。类型化复制仍为O(n)，连续增长的账本总工作量仍可能接近O(n²)，本轮未承诺任意长任务开销恒定。

## 适用范围

这是计量与调度合成探针，没有真实模型、业务服务或工具副作用，不评价答案质量、生产吞吐或费用；计时不含Scope装配与Builder构建。存活堆含运行时及活跃账本，以原始JSON为准；不与峰值内存混用。
