# 可复现评测（合成数据）

运行日期：2026-10-26。所有题目、文档均为合成场景，没有生产数据，不构成与 Eino 的性能或能力对比。原始 JSON 保留失败，不筛选成功样本。

## RAG

```sh
go run ./examples/evaluation/retrieval
OPENAI_API_KEY="$DEEPSEEK_API_KEY" OPENAI_BASE_URL=https://api.deepseek.com \
OPENAI_MODEL=deepseek-flash go run ./examples/evaluation/retrieval -live
```

支持 `-dataset`、`-k`。默认 6 篇中英文支持文档、6 个问题。离线 BM25 与真实 LLM 重排序后的 Recall@2、MRR 均为 1。DeepSeek 实测每题一次重排序、一次回答，共 12 次模型调用，报告 2398 Token；来源编号有效率、标注来源 precision/recall 均为 1。

这些引用指标只检测引用编号及标注来源，**不测量逐句事实蕴含、无引用的幻觉或回答质量**。不能称为“100% 正确”。原始文件：`2026-10-26-retrieval-offline.json`、`2026-10-26-retrieval-deepseek.json`。

## 推理策略

```sh
OPENAI_API_KEY="$DEEPSEEK_API_KEY" OPENAI_BASE_URL=https://api.deepseek.com \
OPENAI_MODEL=deepseek-flash go run ./examples/evaluation/strategies -live
```

相同题目、模型与预算，每个策略每题最多 8 次调用、单次输出上限 800 Token、已观测总量达到 10000 Token 后禁止后续调用、90 秒超时。温度 0.2。每题轮换策略顺序，未禁用供应商缓存。ToT 使用深度 2、分支 2、beam width 1、LLM 评分；ReAct MaxSteps 为调用上限，CoT 使用 zero-shot。未配置工具，不能据此评估工具使用能力。

| 策略 | 严格答案格式通过数 | 模型调用总数 | Token 总量 | 总耗时（秒） |
|---|---:|---:|---:|---:|
| CoT | 3/3 | 3 | 715 | 4.30 |
| ReAct | 1/3 | 3 | 1029 | 6.04 |
| ToT | 0/3 | 18 | 9755 | 51.09 |

评分要求最终输出带 `ANSWER: 数字`，或输出本身就是期望数字。ReAct 两次解析失败；ToT 一次搜索失败、两次未输出所要求的最终答案格式（推导中包含正确数字）。因此此表衡量该题集上的**严格输出契约与结果匹配**，不等于数学正确率或通用策略排名。题目要求的 ANSWER 标记可能与策略自身格式竞争；需要单独评估格式兼容性，不能将解析失败直接归因于模型推理差。

`-input-price`、`-output-price` 可传入每百万 Token 的价格；未提供价格或用量报告不完整时不输出成本，不能将缺省成本当作 0。当前简单估算不区分缓存折扣。Token 阈值依据响应后报告，最后一次调用可能超额，**不是硬性计费上限**。同样的预算上限不代表各策略使用相同 Token 数；原始报告记录真实消耗。

## 输出契约补充轮

保留上面的基线报告，新增两次完整运行记录，没有删除失败题目：

- `2026-10-26-strategies-strict-validation.json`：加入严格检查后的第一次复测。ReAct 3/3、CoT 3/3、ToT 1/3；ToT 两次返回无效评分，错误已被显式报告。
- `2026-10-26-strategies-output-contract.json`：将评分与完成检查协议放入 system 消息、隔离题目格式要求后的复测。题目、模型、温度、调用预算、Token 上限、超时、顺序轮换和搜索参数与基线相同。

| 策略 | 基线格式通过数 | 补充轮通过数 | 补充轮调用总数 | Token 总量 | 总耗时（秒） |
|---|---:|---:|---:|---:|---:|
| ReAct | 1/3 | 3/3 | 3 | 925 | 5.26 |
| CoT | 3/3 | 3/3 | 3 | 695 | 4.13 |
| ToT | 0/3 | 2/3 | 14 | 6174 | 32.80 |

本次 ReAct 保持 `MaxParseRetries=0`，结果没有依赖新增的修复请求。ToT 不再检查“问题根节点是否已经是答案”，其最终验证/输出请求计入同一 8 次调用上限。`agent_usage` 与外围计量器的报告一致；生成、评分、完成检查、最终输出均纳入统计。

评测器现在同时要求 `agent_status=success` 和数值匹配，不接受 partial 的中间结果作为成功。当前成功匹配方式仍是最后一个 ANSWER 数值标记或完全匹配的数值，不是事实蕴含评估。题目本身、模型响应具有随机性；三道合成题不足以建立统计显著性，也不能将耗时或 Token 差异解释为普遍性能提升。

ToT 在 apples 题仍报 `model returned no candidate thoughts`，调用 4 次后停止，没有成功答案；没有通过扩大预算或伪造结果让测试变绿。后续应补充候选生成格式、截断响应诊断和更大题集，再决定是否引入受预算约束的生成修复。

本轮验证包括多行/加粗/中文答案标记、工具参数中引用答案标记、ReAct 重试耗尽、ToT 各阶段错误与评分有效性、四种搜索策略的完成检查错误、最终答案入口一致性、预算耗尽、用量累计和消费者提前停止。全仓短测试通过；变更相关包 race 与 Lint 通过。兼容变化与调用方式见 [能力指南](../guides/PRIORITY_CAPABILITIES.md#推理输出契约补充)。
