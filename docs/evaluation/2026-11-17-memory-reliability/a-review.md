# A 部分人工复核（Task 9 Step 3）

- 运行目录：`/tmp/cs-scenarios/20261117-190225`（results.jsonl 90 行，9 场景 × 10 次，infra 0）
- 复核范围：`judge_ok==false` 或 `state_ok==false` 的 29 项，加每场景 2 个评审判对的抽样项。
- 抽样命令（每个场景执行一次，`<s>` 为场景名）：

```bash
jq -r --arg s <s> 'select(.scenario==$s and .judge_ok==true) | .repeat' results.jsonl | sort -n | shuf -n 2 --random-source=<(yes)
```

  抽样结果：abstain 2,5；forget 5,4；isolate 2,5；multi 6,8；pinchain 2,5；premise 3,10；recall 5,9；temporal 6,3；update 2,1。temporal 3/6 和 update 1/2 本身就在失败项里，所以复核项共 29 + 18 − 4 = 43 项。
- 口径：
  - 「自动评审」写作「状态/评审」，T 表示通过，F 表示不通过。
  - 「复核结论」判断该项是否真正达到场景意图：答复要对，有效记录也不能有真实缺陷。
  - 「归类」是真实失败的根因阶段；自动检查判错而系统没错时记为 judge。
  - 「评审误判」指状态检查或 LLM 评审中至少一层与复核结论不一致。
- 答复链路说明：发给客户的最终答复是分流（triage）在 FINISH 时复述的 reply，见 `graph.go` 的 `finalReply`。分流没有接入长期记忆。下文「成员答复」指 general 成员的 `model/turn/*` 输出。

## 缺陷候选

复现命令统一为 `GOAGENT_LIVE=1 CS_SCENARIO_ONLY=<name> CS_SCENARIO_REPEATS=10 … go test -run TestLiveMemoryScenarios`。

1. **answer：分流复述丢失成员基于记忆的结论。** 分流没有长期记忆，客户最终收到的是分流在 FINISH 时复述的 reply，成员答复里引用记忆的部分（蓝色、X200、「没有相关记录」）在复述中被删掉。
   - 复现：`CS_SCENARIO_ONLY=premise`、`recall`、`forget`。
   - 影响：premise-04/09、recall-03/10、forget-01 共 5 项。记忆已正确召回，客户却看不到；这是本轮最大的单一失败来源。
2. **recall：召回块和 memory_search 结果只保留日期，同日的多条记录无法排序。** recall.go:181 用 `time.DateOnly` 渲染，记录按得分排列，工具结果也不带时间。
   - 复现：`CS_SCENARIO_ONLY=temporal`。
   - 影响：temporal-01/02/04/05 共 4 项模型如实答「无法判断先后」；07/08 答对只是因为得分顺序碰巧与时间一致。所有「最早/最近」类问题都受影响。
3. **extract（不能排除 consolidate noop）：第 2 张工单「充电器发烫」没有留下任何有效记录。** 现存的断连记录 content_rev=1，且创建于第 2 张工单之前，排除了 update 和 invalidate 两条路径。剩下两种可能：抽取返回空，或整理阶段误判 noop。存储容器在运行结束后已删除，抽取输出没有留存，无法再细分。
   - 复现：`CS_SCENARIO_ONLY=temporal`。
   - 影响：4/10 次（temporal-03/06/09/10）丢失同一客户的第二个问题。建议复现时开启抽取与整理决定的日志，确认是哪个阶段。
4. **tool：成员按客户的错误前提调用 `memory_replace`，覆盖了正确记忆。** 例：premise-07 中 2428b283「蓝色款」被改成 fc008351「红色款…以用户最新说法为准」。
   - 复现：`CS_SCENARIO_ONLY=premise`。
   - 影响：1/10 次，但会持久污染长期记忆，后续工单都会继承错误事实。
5. **answer：记录已在召回中，模型仍不使用或含糊其辞。**
   - multi-04：两条订单事实都已召回，却答「没有订单号」。
   - update-04：把「已改为上海浦东」当作假设。
   - forget-02/03/10：搜索结果为空，却答「验证后可在账户中查看」。
   - 复现：`CS_SCENARIO_ONLY=multi`、`update`、`forget`。
   - 影响：共 5 项。
6. **评审缺陷（不属于系统缺陷，供修订评测用）：**
   - update 的 `validLacks("朝阳")` 子串规则会把「新事实提及旧值」误判成旧记录残留，误判 9/10 次。建议改为只检查是否存在把朝阳当作现行地址的记录，或改用 LLM 判状态。
   - LLM 评审对同构答复判定不一致：update 1–3 与 5–10、forget 06/08 与 01–03/10。
