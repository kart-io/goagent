# 记忆运行与恢复

[English](MEMORY_RUNTIME.md) · [记忆API](../../memory/README.md)

长期记忆提供可撤回的上下文。业务输入、已验收产物、审批、效果回执和执行预算由宿主的持久执行状态保存。遗忘记忆不会删除这些记录，也不会授权重新写入。业务产物中留存的个人数据须由宿主另行实施保留与删除策略。

## 上下文选择

`memory.Config.ContextLayout == nil` 保持原有选择方式及 `Identity()`。需要限制钉住记录时，传入 `&memory.ContextLayout{CoreRunes: n}`。`CoreRunes` 在原有 `RecallRunes` 总额内计算完整记录行及分隔符；零值排除所有钉住记录。放不下的钉住记录不能从普通排序通道重新进入；未用额度可供其他召回记录使用。这是字符额度，不能当作token或计费估算。

`ExplainSnapshot(ctx, query)` 返回 `Snapshot`、`SnapshotExplanation` 和 `error`。解释中记录同一次选择的引用和空间分配，不含记录正文。`Snapshot` 保存引用；`Hydrate` 根据当前命名空间、scope和正文版本过滤这些引用，不能重新选择替代记忆。命名空间须由受信租户、用户身份绑定。

Builder现已支持零工具Agent自动召回。新轮次提交 `plain-memory/1` 或 `plain-none/1`；没有 `RecallMode` 的旧轮次维持原有模型意图，回放不追加记忆操作。已完成请求直接回放，不再访问模型。每次新的物理请求前，包括同轮次可恢复重试，Builder再次还原相同引用，移除已遗忘内容。已经提交给模型的请求无法撤回。

新plain自动召回不能与 `RequestHook` 同时使用。native工具Agent的宿主不得在hook内复制或改写自动召回块，否则可能破坏持久意图验证。新协议轮次已有model/use记录却缺召回记录时，恢复报错，不能静默改写请求。

## 后台维护准入

`Config.Background == nil` 保持原有维护行为。需要约束后台付费调用时，宿主配置 `BackgroundConfig`：

- 持久 `budget.Controller`，使用稳定窗口 `RootKey`、正数 `MaxModelRequests` 与 `MaxReservedTokens`，以及预期的窗口截止时间。
- 正数 `MaxInputRunes`、`MaxOutputRunes`、`MaxOutputTokens` 和 `MaxDerivationsPerPass`。
- 保守覆盖完整请求的 `EstimateChat`、`EstimateEmbedding`；`EstimatorVersion` 须与预算的 `TokenPolicyVersion` 一致。
- `SingleRequestClients: true` 是宿主承诺底层模型与嵌入客户端不会重试或拆分物理请求。作出承诺前须关闭客户端包装层的这些行为。

每个物理维护请求，包括JSON修补和embedding，分别准入并记录证据。持久化的命名空间、scope及请求序号防止重启后复用键；未知用量保留为未知。后台去除前台journal、归属和预算绑定，同时保留取消及截止时间。在线 `Recall`、`Remember` 的embedding需要宿主单独准入，不能借后台窗口。

社区和反思工作持久记录dirty/done进度、技术尝试数、重试时间、暂停及预算阻塞窗口。每轮每命名空间、每类别最多启动 `MaxDerivationsPerPass` 个派生。技术失败有界退避，五次后暂停；输入超长在请求前暂停。新预算窗口只解除预算阻塞，不清除技术失败；同一窗口重启仍保留已消费额度。

修复技术问题后，宿主可在对应命名空间显式调用 `MarkDerivationsDirty`，登记社区和反思工作并清除技术暂停及尝试数。预算阻塞键、物理请求序号保持。普通输入变化不会悄悄重置暂停。模型额度耗尽时，删除和索引清理仍可完成；索引更新失败保留修补队列。

## 存储升级与回退

记忆状态写入格式现为 `/4`。可读取真实 `/2`、`/3` 数据，派生进度参与克隆、增量提交、压实及scope操作。旧读者拒绝 `/4`，不支持新旧写者混跑。

1. 停止共享存储的Agent和维护写者，备份完整持久存储及外部索引，并保留回退窗口内的删除日志。
2. 所有参与进程一起升级。续跑使用原图、成员Manifest、审批键和预算根。
3. 验证召回与删除，再运行维护核对派生索引。不能清除待处理工作或attention来绕过升级问题。
4. 数据回退时恢复兼容备份，并重放备份后的删除。只替换二进制无法降级 `/4`；只恢复备份而不重放删除可能让已遗忘内容重新出现。

改变布局会改变新的记忆身份，不应在持久运行中途更改。后台控制器是运行时准入策略，不进入记忆身份；恢复快照仍须验证命名空间和scope。

## 验证与评估

Harness规划示例演示本地材料处理与持久等待。联合测试覆盖实际非空召回、两次请求之间遗忘、在线与后台预算隔离、未知写效果和真实进程重启。这些检查验证执行与恢复契约；模型回答质量、并行耗时与布局节省须另做真实试验，不能从离线结果推出。

比较布局时，把同一份已形成记忆快照复制到隔离存储，分别运行nil布局和配额布局；关闭记忆组使用相同原始历史和上下文上限。形成、前台回答和独立判分分别计费，每次重试在物理请求边界计数；失败、未开始项保留在预登记分母中。引用只能帮助追溯，存在引用不等于结论正确。
