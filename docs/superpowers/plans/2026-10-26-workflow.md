# Workflow Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; finish with a fresh read-only code review.

**Goal:** 在主模块提供可编译、支持分支/并行/有界循环的通用流程编排。

**Architecture:** workflow.Graph[T] 构建同类型状态图；编译不可变图定义，执行复用 core.StreamRunnable；并行节点显式 Clone 和 Merge。

**Tech Stack:** Go 1.25、core.Runnable，无新依赖。

**Spec:** docs/superpowers/specs/2026-10-26-workflow-design.md

## Global Constraints

- 保留已有工作区改动，主模块不依赖 Eino。
- 默认 MaxSteps=100、MaxConcurrency=4；错误和取消不产生成功 Done。
- 流能力为 steps，透传节点事件，不提供跨节点 Token Transform 或持久化恢复。

## Review Focus

- 条件路径汇合不得等待未选择的分支。
- 并行错误/panic/取消后 worker 退出，Merge 不运行。
- map/slice 状态须显式复制，结果按注册顺序汇合。
- 自定义 Runnable 的重复/缺失终态或迟到错误不能被吞掉。
- 编译快照和多个执行不共享调度状态。

- Task 5：59 个主模块测试包通过；workflow race 连续 10 轮通过；Eino 子模块 race、go vet、同步/事件流示例和 diff 检查通过。
- Final review：独立只读审查，无问题；另以独立 race harness 验证延迟流关闭与 100 次背压取消。详见 docs/evaluation/2026-10-26-workflow-validation.md。
- Ruling：同一状态 T + 显式 Adapt — 保持类型约束并复用 Runnable — 代价是没有自动异构字段映射。
- Ruling：并行必须提供 Clone/Merge — 明确隔离与汇合语义 — 代价是应用负责深复制可变状态。
- Ruling：原生节点同步执行，并行取消等待 worker 退出 — 避免工作遗留到图结束之后 — 代价是不响应 context 的业务函数可阻止节点结束。
- Ruling：steps 流 + 最终状态边 — 兼容现有 Runnable 事件和终态契约 — 代价是本轮不提供跨节点 Token Transform 或持久化图恢复。
- Deferred minors：无。
