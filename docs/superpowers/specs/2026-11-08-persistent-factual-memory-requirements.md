# GoAgent 持久事实记忆服务需求

日期：2026-11-08。状态：需求基线，目标在 GoAgent 核心仓库实现。

## 1. 背景与问题

GoAgent 已有 `memory` 包，包含 `MemoryEntry`、分层记忆、向量存储接口和嵌入接口。但当前 `LongTermMemory` 将正文和类型索引保存在进程内 map；重启后无法恢复。向量存储单独持有 ID 与 embedding，不足以还原事实正文和生命周期。当前长期记忆搜索也没有执行向量召回。

会话日志、事实记忆和知识库的用途不同，不能相互替代：

| 数据 | 回答的问题 | 主要责任 |
| --- | --- | --- |
| 会话日志 | 曾经说过什么、执行过什么 | `core/session` 与执行日志存储 |
| 持久事实记忆 | 以后仍有用的用户事实、偏好和已确认经验 | 本需求的 MemoryService |
| 知识库 | 某份文档或业务资料具体写了什么 | 现有 Retriever/RAG 组件 |

目标是在 GoAgent 仓库中交付稳定、公开、可扩展的 MemoryService 抽象与 Agent 接入能力，使核心和外部模块都能提供可持久化、按作用域隔离、可检索且可管理的事实记忆实现。持久化实现可以由外部模块提供；核心不得把服务绑定到某个数据库或向量厂商。单有接口仍不足以完成需求：核心还须提供完整的数据契约、上下文装配、错误语义、生命周期约定和实现者验收工具。

## 2. 目标使用者与主要场景

| 使用者 | 场景 |
| --- | --- |
| GoAgent 宿主开发者 | 为 Agent 配置持久事实记忆、作用域和召回策略 |
| 最终用户 | 查看、纠正、替代或删除与自己有关的记忆 |
| Agent | 在新会话中召回经过保存、且当前仍有效的相关事实 |
| 运维人员 | 确认持久化、索引和召回是否正常，不暴露事实正文到日志 |

核心案例：用户在一次会话中保存“我偏好用中文回答”；宿主重启后，用户在新的会话中提问，Agent 在授权的用户/Agent 作用域内召回该偏好。用户之后可以查看、修改或删除它；过期或被替代的版本不再进入上下文。

## 3. 范围与实现位置

### 本期范围

- 在 GoAgent 核心仓库实现公开的 MemoryService/存储抽象、数据类型、错误语义、配置与 Agent 上下文召回集成。
- 外部 Go 模块能够仅依赖公开 API 实现并注入自己的 MemoryService 或存储适配，不需要修改 GoAgent 核心、不需要依赖未导出的类型或内部实现。
- 抽象契约要求实现同时持久化事实正文、元数据、来源和生命周期状态，并提供持久检索索引或可验证的索引重建能力；进程内 map 可用于测试或开发，但不能宣称满足持久化实现。
- 提供外部实现者可运行的契约测试/一致性套件和至少一个完整接入示例。某个特定数据库或向量引擎的生产适配不要求内置于 GoAgent 核心。
- 提供显式写入、查询、列表、修改/替代、删除、失效时间和上下文召回能力。
- 默认按租户、用户和 Agent 隔离；跨 Agent 共享须由宿主显式配置和授权。

### 不在本期范围

- 自动从每次对话中抽取、合并或推断事实。调用方可显式保存事实；自动提取策略另行设计。
- 用事实记忆替代会话日志，或把完整对话历史自动复制进事实库。
- 用事实记忆替代文档索引、RAG、业务知识库或会话上下文压缩。
- 管理 Web UI、组织权限后台、自动跨租户共享、自动事实可信度判断。
- 依赖 goagent-contrib 的 pgstore 才能运行本服务；核心仓库必须具有自己的可用实现和验收案例。

具体存储、迁移格式和索引引擎由实现者选择；技术设计确定核心抽象边界和参考实现策略。外部实现不得因后端能力差异静默放宽持久化、隔离、删除和恢复语义。

## 4. 核心术语与数据约束

| 术语 | 定义 |
| --- | --- |
| 事实记忆 | 一条可单独查看、更新、替代、过期或删除的文本信息，不是完整会话或文档副本 |
| 作用域 | 事实可被哪些主体读取；默认至少包含 TenantID、UserID、AgentID |
| 来源 | 说明事实由哪次会话、哪份文档或哪次人工确认产生；来源记录可带引用位置或事件序号 |
| 有效状态 | 事实可召回的状态；失效、删除、过期和被替代的事实不得召回 |
| 替代关系 | 新事实替代旧事实时保留可审计的关联，旧版本退出默认召回 |
| 检索索引 | 供语义或关键词查询使用的数据；不得成为恢复事实正文的唯一来源 |

所有写入和查询由可信宿主上下文提供租户及主体身份，不能接受客户端正文覆写作用域。正文、元数据、来源和索引须能关联到同一条事实及其修订。系统不得将 API 凭据或其他秘密默认保存为事实。

## 5. 功能需求与验收标准

### 5.1 持久化与作用域

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| PM-01 | 按租户、用户、Agent 保存事实 | 新写入的事实只对匹配作用域的查询可见；不同租户绝不能互相读取 |
| PM-02 | 支持显式共享策略 | 默认隔离；启用共享时范围由宿主配置确定，并且跨 Agent 查询需显式授权 |
| PM-03 | 持久保存事实与元数据 | 进程退出并重新创建服务后，事实正文、来源、状态、标签和时间信息仍可读取 |
| PM-04 | 持久索引或重建 | 重启后可继续检索；若索引丢失，可从持久事实重建，不能因索引重建失败返回错误事实或跨作用域结果 |
| PM-05 | 并发安全 | 同一事实并发修改或替代时，不产生两个同时有效的冲突版本；冲突明确返回给调用方 |
| PM-05a | 外部实现接口 | 外部 package 可通过公开接口实现 Provider，并从 Builder/宿主配置注入；接口不含未导出方法，核心不依赖具体 Provider 类型 |
| PM-05b | 实现者契约套件 | 外部 Provider 可运行 GoAgent 提供的 conformance suite，覆盖作用域隔离、持久恢复、并发修订、过期、删除和索引一致性 |
| PM-05c | 能力与生命周期声明 | Provider 的关闭、并发调用、持久性、过滤与索引能力有公开约定；缺少必需能力时初始化明确失败，不静默降级为内存实现 |
| PM-05d | 持久执行召回快照 | 同一 durable Run 重启恢复时使用相同事实 ID/Revision 快照；相关事实被删除、撤权或失效时明确拒绝续跑，不悄悄换一组事实 |
| PM-05e | 响应缓存隔离 | v1 启用事实记忆时，缓存必须同时 no-read/no-store；不支持公开 bypass signal 的缓存实现不能组合使用 |

### 5.2 来源与生命周期

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| PM-06 | 保存来源信息 | 可查看事实来自会话、文档或人工确认；会话来源含 SessionID，文档来源含文档标识，人工确认含操作者和确认时间 |
| PM-07 | 修改事实 | 修改后后续读取和召回返回新内容；修改前后的来源关系可追踪，旧内容不被误当作当前事实 |
| PM-08 | 替代旧事实 | 替代操作记录新旧关系；旧事实退出默认搜索，新事实可正常召回 |
| PM-09 | 支持失效时间 | 已过期事实不出现在 Get、List 或 Search 的有效结果中；清理任务是否异步不影响失效语义 |
| PM-10 | 删除事实 | 删除后 Get/List/Search 均不可再读取该事实，相关检索向量也不可召回；重复删除行为稳定且可定义 |

### 5.3 检索与上下文集成

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| PM-11 | 按查询召回事实 | 返回相关度、来源与有效状态；查询严格受作用域、状态、类型和失效时间约束 |
| PM-12 | 支持显式筛选和限制 | 调用方可限制返回数量及可选标签/类别；空查询、非法数量和超限输入得到明确结果 |
| PM-13 | 在模型调用前注入召回 | 启用记忆的 Agent 在构造模型上下文时可获得授权且有效的事实；未启用记忆时行为不变 |
| PM-14 | 控制注入规模 | 宿主可设置最大条数或 token/字符预算；超限结果按确定规则截断，不突破预算 |
| PM-15 | 保持事实与策略分离 | 召回内容以明确标记的非用户事实上下文传给模型，不能覆盖 system/developer policy，也不伪装成用户发言 |
| PM-16 | 明确失败策略 | 后端/索引故障按配置策略处理；缺失身份、非法共享范围、scope 不匹配等授权错误始终失败，不能被 best-effort 吞掉 |
| PM-24 | 会话与模型上下文分离 | 记忆文本不写入 SessionLog、Handle 对话历史或 durable journal；用户可见的原始会话事件保持原样 |
| PM-25 | Durable Run 稳定性 | durable 执行对每次逻辑请求固定召回快照身份；因事实变更无法恢复时返回明确冲突，不使用新召回结果执行旧 Run |
| PM-26 | 缓存安全 | 启用事实记忆的请求不能读取或写入响应缓存；同一共享缓存中普通 Agent 不能命中记忆 Agent 写入的答案 |
| PM-27 | 写入幂等 | Save/Supersede 接受调用方稳定幂等键；同作用域同键同请求返回不可变操作收据，同键不同规范化请求冲突；重放重新授权且不返回缓存正文；键保留期后返回 IdempotencyExpired，永不因键回收重建已删除事实 |
| PM-28 | 明确共享作用域 | 首批区分 agent-private 与同用户 allowlisted-agent shared；调用身份与目标事实作用域分开，宿主提供授权作用域集合，未知模式与越权目标明确拒绝 |
| PM-29 | Embedding Profile | 索引记录模型/版本、维度和距离度量；模型空间变更必须创建新的 IndexGeneration、重建后切换，禁止混合不同向量空间查询 |
| PM-30 | 召回选择策略 | 支持宿主标记少量常驻偏好/事实；这些事实仍受授权、有效期和注入预算约束。普通语义召回应用相关性阈值，不相关时可返回空集合 |
| PM-31 | 生命周期安全的幂等回放 | 幂等记录只保存操作引用与请求摘要；更新/替代/过期时仅回放原收据，删除时返回稳定 Deleted/Gone，撤权时拒绝；任何状态均不泄露旧正文或复活事实，去重键摘要只保留不可逆 digest tombstone 以拒绝过期键，正文与原结果按策略清除 |
| PM-32 | 索引维护与恢复入口 | 持久 Provider 支持运行 Worker、查询/重试失败任务、启动和跟踪全服务索引重建；以全局 StoreSequence 做 cutoff/追平；重建期间可同时解析旧、新 Embedder 并双写，追平后原子切换代际；无需内置 HTTP/UI |
| PM-33 | 作用域清空与生命周期 | 定义 DeleteScope 的即时不可见边界、并发写入规则、可恢复清理状态和完成判定；用户/Agent 注销流程先封禁普通写入，再以独立 ClearAccess 授权清理目标 scope |
| PM-34 | 可查询变更链 | 提供有界分页变更记录，包含 revision、动作、操作者、时间、来源引用和替代关系，不保留已删除正文 |
| PM-35 | 输入边界与背压 | 对事实正文、元数据、分页、Worker 并发和待办积压设置有限额默认值和 Provider 能力边界；超限明确拒绝且不得静默丢弃已接纳事实；清理/删除拥有不受普通写入积压限制的保留容量 |

上下文注入不能把记忆事实追加为会话日志中的用户发言。若宿主选择将召回摘要记录在可观测轨迹中，必须限制敏感正文暴露并可关闭。常驻偏好是召回策略标签，不得绕过 scope、状态、TTL、授权或预算约束。相似度分值统一为 [0,1] 且越大越相关；外部 Index 必须转换其距离分数或报告不支持阈值筛选。

### 5.4 记忆管理

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| PM-17 | 查看单条事实与分页列表 | 可按作用域、状态、标签、来源和时间过滤；不授权主体不能枚举其他作用域的 ID 或内容 |
| PM-18 | 纠正与替代 | 用户或宿主可修改错误事实，或以新事实替代；所有后续召回遵循当前有效版本 |
| PM-19 | 用户删除 | 可删除单条事实及授权范围内的全部事实；删除范围必须精确匹配当前主体或显式授权范围 |
| PM-20 | 有界审计 | 记录创建、修改、替代、删除的主体与时间；删除审计不得再次保存已删除的事实正文 |

### 5.5 可观测性与可靠性

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| PM-21 | 记录服务运行结果 | 可观测写入、查询、索引更新/重建的耗时、错误和数量；日志默认不含事实正文、embedding 或凭据 |
| PM-22 | 保证事实与索引一致 | 保存或删除遇到索引后端故障时，不产生“成功但永远不可查”或“已删除仍可召回”的静默状态；提供可重试或重建路径 |
| PM-23 | 遵循上下文取消与超时 | embedding、存储和检索调用遵守 context；调用取消后不继续无限期占用资源 |

## 6. 安全与隐私要求

- TenantID 必须作为强制隔离条件；查询不能先全局召回再由调用方过滤。
- 用户与 Agent 身份来源于可信宿主上下文。请求中的主体字段只能作为待验证参数，不能作为授权依据。
- 跨 Agent 共享必须是显式策略，且有测试证明默认配置仍然隔离。
- 用户删除后，事实不能通过关键词、向量、缓存或列表接口重新暴露。备份清除周期由宿主策略披露。
- 结构化日志、错误信息、指标标签不得写入事实正文、embedding、秘密或完整用户输入。
- 召回事实视为不可信数据，只能作为上下文证据，不得获得高于系统/开发者指令的权限。

## 7. 关键端到端验收案例

1. **重启恢复：**通过公开接口接入持久 Provider，写入用户偏好，关闭并重新创建 Provider 后，按 ID 和查询都能读回原事实及来源。
2. **用户隔离：**同租户两个用户写入近似事实，彼此 Search、List、Get 均不能看到对方数据。
3. **Agent 隔离与共享：**同一用户的两个 Agent 默认互相不可见；宿主显式启用共享后，只有配置的共享范围能够召回。
4. **来源可追溯：**保存会话来源、文档来源和人工确认来源，分别检查其来源标识、引用和操作者元数据。
5. **纠正与替代：**将“用户住在杭州”改为“用户住在苏州”，旧内容退出有效搜索，新内容可召回，修订链仍可检查。
6. **过期：**写入已过期与未过期事实，查询和上下文注入只包含未过期事实。
7. **彻底删除：**删除一条已建立向量索引的事实后，通过 ID、关键词、语义查询和重启后查询都无法再取回正文。
8. **上下文注入：**启用记忆的 Builder 在下一次模型调用前注入相关事实，遵守注入预算；关闭记忆时请求内容与原有路径一致。
9. **后端故障：**分别注入正文存储、embedding、索引写入和检索失败，验证结果遵从失败策略并留下可观测错误，不返回跨作用域或陈旧事实。
10. **并发更新：**两个调用并发替代同一事实，只有一个版本成为当前有效事实，另一操作得到确定的冲突或按设计合并。
11. **写入超时重试：**持久提交成功但客户端超时后，以同一幂等键重试只得到同一不可变操作收据，不重复创建或返回缓存正文。
12. **durable 审批恢复：**Run 等待审批时修改或删除其召回事实，重建宿主后不得静默改用新事实；按规则拒绝续跑或恢复相同仍有效快照。
13. **缓存 no-read：**启用事实记忆的 Agent 不读取输入专用响应缓存；不同用户相同输入不能命中之前缓存的回答。
14. **缓存 no-store：**事实记忆 Agent 生成回答后，使用相同输入的普通 Agent 即使共享同一 CacheMiddleware 也不能命中刚才的响应缓存。
15. **乱序索引更新：**旧 MutationVersion 的延迟 Upsert 不覆盖新 revision；删除后的迟到 Upsert 不可召回，并能由 outbox/对账清理。
16. **更换嵌入模型：**切换模型 profile 时创建新 IndexGeneration；旧向量不会与新查询向量混用；重建期间同时提供旧/新 profile Embedder，以全局变更水位追平后原子切换。
17. **常驻偏好与相关性门槛：**标记为常驻的语言偏好在与语言无关的问题中仍可召回；不匹配查询且未标记常驻的事实因低于阈值而不返回。
18. **幂等回放与删除：**Save 后删除事实，重启后使用原幂等键重试；返回稳定 Deleted/Gone 状态，不返回正文、不创建新事实。
19. **索引故障恢复：**制造持续索引失败直至重试耗尽；通过公开维护接口查询失败、修复后重试并恢复召回；进程重启后维护状态和任务仍可恢复。全服务重建时旧代际持续服务，新代际追平 mutation 水位后原子切换。
20. **作用域清空：**清空多页事实时，在清理期间重启；清理前已存在事实立即不可见，清理完成状态可查询；清空期间 scope 写入明确拒绝；普通写入 outbox 满时 Delete/DeleteScope 仍可逻辑生效并进入保留的清理容量。
21. **注销清理：**宿主封禁指定用户或 Agent 的普通写入后，由独立 ClearAccess 管理授权清空其作用域，确认索引 tombstone 和清理状态完成；Session 删除或 Fork 不隐式改变事实记忆。
22. **变更链可查：**Save、Update、Supersede、Delete 后按权限分页查看完整动作与来源引用；删除后审计记录不暴露旧正文。
23. **边界与背压：**超长正文/元数据、非法或超限分页请求在提交前拒绝；索引待办达到配置容量后拒绝普通新写且不产生半写事实，但 Delete/DeleteScope 仍可通过预留清理容量生效。
24. **稳定分页：**相同 scope/filter 的游标按固定顺序续页；跨 scope/filter 使用游标或格式损坏的游标明确拒绝；起始高水位固定候选成员；每页按当前授权和生命周期 hydrate，删除/撤权成员可消失，原位更新返回当前 revision；剩余成员不重复，不承诺历史正文快照。

## 8. 完成定义

- 公开 API、服务抽象、Builder 注入点、示例和 Provider 契约测试位于 GoAgent 仓库；GoAgent 核心不绑定 `goagent-contrib` 或任何具体外部实现。
- 有一个通过契约套件的可运行实现用于自动化验收；它可以是仓库内参考实现或外部适配示例，但持久化验收必须使用真正可重启恢复的 Provider。
- 有独立于 GoAgent 内部包的外部实现示例，能从外部 Go package 实现接口、注入 Builder、通过一致性测试并在进程重建后恢复事实。
- 进程重启恢复、作用域隔离、事实正文与检索索引一致、纠正/替代/过期/删除、上下文召回均有自动化验收。
- 为至少一个实际持久后端提供可复现案例；仅使用内存存储的测试不能替代持久化验收。
- 更新 `memory/README.md` 和相关 Builder 文档，说明事实记忆与会话日志、RAG 的边界、配置和恢复行为。
- 公共方法有 GoDoc；错误、取消、关闭与资源生命周期有明确约定。
- PM-30～PM-35 均有外部可观察契约及确定性验收案例；注销与数据导出由宿主调用公开接口完成，不要求内置 HTTP/UI。
