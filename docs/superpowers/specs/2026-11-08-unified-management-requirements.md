## 1. 目标与使用者

把宿主里分散的执行、会话、存储和 HTTP 接入装配为一致的管理服务，使业务能够持续运营多个 Agent。

| 使用者 | 要完成的工作 |
| --- | --- |
| 业务开发者 | 在已有 Go 服务中注册 Agent 工厂，接入存储、鉴权与运行资源 |
| 运营人员 | 发布配置、启停 Agent、查会话和任务、定位等待与失败 |
| 审批人员 | 查看自己有权处理的操作，批准或拒绝，留下身份和理由 |
| 值班人员 | 检查积压、恢复中断任务、核对未知效果、观察资源消耗 |

核心场景：注册并发布 Agent → 创建固定版本的 Session → 提交 Task → 持久等待审批 → 处理决定 → 自动续跑 → 查询结果与资源证据。HTTP 断开或宿主重启不得丢失已接纳的任务与决定。

## 2. 范围与决策状态

下表中的“首批”是建议的后续开发范围，不代表用户已经批准具体技术选型。需求整理本身已获授权。

| 范围 | 本轮文档 | 建议首批开发 | 后续独立阶段 |
| --- | --- | --- | --- |
| 五类资源的完整管理闭环 | 需求、契约、实施与验收 | Go 服务、HTTP API、Postgres 存储、离线接入例子 | 管理界面 |
| 跨实例任务发现 | 明确一致性与索引 | 多 API 共享接纳与查询，一个活动执行宿主 | 多 worker 并行、分片与自动接管 |
| 业务权限 | 身份来源、操作点、隔离标准 | 宿主注入权限实现，逐资源校验 | 权限后台、组织与角色配置界面 |
| 执行与工具 | 明确复用边界 | 复用 GoAgent，提供原生 Builder/持久图适配 | 更多业务 Runner 与执行后端 |

首批不引入管理前端、Cron、计费结算、任意 Go 代码热加载或通用工作流编辑器。仍需处理首批范围内的异常与恢复，不以空接口或内存实现代替持久保证。

## 3. 概念与身份

| 概念 | 定义与约束 |
| --- | --- |
| Agent | 可运营的逻辑资源，含启用状态与当前发布版本；不是某个 Go 对象指针 |
| AgentVersion | 不可变的配置与实现引用；包括 Runner 类型/实现版本、模型配置、工具及策略版本、非秘密配置摘要 |
| Session | 固定绑定一个 AgentVersion 的业务会话，拥有独立历史与 Fork 来源 |
| Task | 一次持久业务请求；多个恢复尝试仍是同一个 Task，使用同一逻辑执行键 |
| Attempt | Task 每次实际进入执行的记录；与模型提供商请求的 attempt 区分 |
| Approval | 某个 Task 在某次等待位置的审批待办；不是执行授权令牌 |
| Command | 已持久接纳但可能尚未应用的提交、恢复或取消操作 |
| Run | 运行查询视图，以稳定 RunID 关联 Task 和多个 Attempt；恢复不改变逻辑 RunID |

所有业务资源均包含 TenantID。租户、操作者和权限来自可信宿主上下文，不能相信客户端正文中的身份。凭据通过引用在运行时解析，版本配置和审计中不保存明文秘密。

## 4. 功能需求与验收条件

### Agent

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| AG-01 | 注册、查询、分页列出 Agent | 注册后跨 API 实例可查询，重复 ID 冲突，不产生第二份资源 |
| AG-02 | 保存配置版本、校验并发布、查询当前版本 | 非法配置不能发布；已发布快照不可修改；发布人、时间和摘要可查 |
| AG-03 | 启用与停用 | 停用阻止新建会话、新任务和执行启动/恢复；已有执行按原流程退出，取消需单独请求 |
| AG-04 | 固定版本重建 | 发布 v2 后 v1 会话仍按 v1 执行；v1 实现不可获取时明确阻塞，不偷偷切换至 v2 |

“配置发布”指宿主已有 Runner 的配置快照发布。部署实现代码及动态加载插件不属于这一操作。回滚通过重新发布已存在版本完成，保留审计。

### Session

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| SE-01 | 创建、查询、分页列出 Session | 固定记录 AgentID、AgentVersion 与创建人，创建中断可核对恢复 |
| SE-02 | 按事件游标查询历史 | 返回顺序与原日志一致；默认隐藏内部快照和秘密字段；不授权者不可读 |
| SE-03 | 按指定序号 Fork | 源不变，分支与源可独立追加；记录实际分叉序号并继承版本 |
| SE-04 | 保证同会话顺序 | 一个会话至多一个实际执行者；等待中的 Task 阻止后续 Task 改写历史 |

首批 Fork 只允许在没有未结束 Task 的源会话上进行，且必须通过一致性校验的轮次结束边界；不支持正在等待审批的历史分支。Fork 从分支开始新任务、新执行键，不向管理 API 暴露原任务的内部恢复键。跨版本迁移单独设计。

### Task

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| TA-01 | 幂等提交与持久接纳 | 相同键/内容返回原 Task，不同内容返回 409；只有数据库提交后才返回已接纳 |
| TA-02 | 查询详情和筛选列表 | 可按 Agent、Session、状态、时间查询 queued、人工等待和 attention 等记录 |
| TA-03 | 取消 | queued 不启动；running 先显示 canceling，真实退出后才确认终态；已完成结果不被迟到取消覆盖 |
| TA-04 | 恢复 | 等待输入或中断时，在原版本、原输入、原逻辑执行键下继续；终态任务不由普通恢复复活 |
| TA-05 | 宿主重启恢复 | 接纳未启动、等待、执行结果已落盘但索引未更新的 Task 均可找回并按证据处理 |
| TA-06 | 不确定效果处理 | 未知外部写入进入 attention；核对前不盲目重新执行 |
| TA-07 | 资源关闭 | 停服先关闭准入、取消本轮执行并等待真实退出，再关闭共享依赖；超时仍保留责任和诊断 |

重试已失败业务属于新的 Task，可记录 `retry_of`；同一 Task 的恢复只适用于原执行的等待、中断或已核对的 attention，不能暗中增加执行预算。

### Approval

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| AP-01 | 列出待审批操作 | 显示安全摘要、所属 Agent/Session/Task、等待时间；只返回有权查看的待办 |
| AP-02 | 批准或拒绝并审计 | 记录可信处理人、决定、理由、时间、目标修订号；并发决定只有一个生效 |
| AP-03 | 可靠触发续跑 | 审批决定与后续命令一起提交；worker 故障只延迟应用，不丢决定、不重做已完成效果 |
| AP-04 | 拒绝行为明确 | 工具拒绝作为工具结果交回模型；图节点拒绝走已定义分支；不支持该语义的适配器在发布时拒绝配置 |
| AP-05 | 等待轮次隔离 | 旧批准不能用于新操作、新参数或循环中的下一次等待；已处理待办的重复请求返回原决定或冲突 |

首批仅支持单次批准，不开放会话级永久授权。业务状态或权限在等待期间发生变化时，执行前仍须重新校验；批准不绕过 Dispatcher Guard 或预算约束。

普通任务恢复不能绕过审批：`task.resume` 只能提交普通输入或已核对的 attention 恢复，审批等待点必须通过 `approval.decide` 保存决定再触发续跑。并行等待中处理一个操作，不得更换其他未处理操作的待办身份或作废其合法决定。

### 运行观测

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| OB-01 | 按 Agent、Session、Task 查询执行与错误 | 查询关联稳定 Run、Attempt、等待和错误分类，不把观测事件当作业务终态 |
| OB-02 | 汇总资源消耗 | 使用持久预算和 usage 证据；回放不重复相加；提供已知字段及完整性说明 |
| OB-03 | 保留未知与未归属 | 未报告 Token、CPU、内存或金额时显示未知；嵌套 Agent 的 self 与 inclusive 不重复累加 |

### 跨资源约束

| 编号 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| CO-01 | 租户与权限隔离 | 伪造 TenantID/ActorID、跨租户关联与枚举均不能获得目标数据或改变状态 |
| CO-02 | 原子接纳与可恢复应用 | 实体、幂等记录、审计、命令原子提交；跨存储操作有确定的核对流程 |
| CO-03 | 稳定分页与资源上限 | 默认 50、最多 200 条，按创建时间和 ID 游标翻页；请求体最多 1 MiB |
| CO-04 | 幂等与保留期 | 幂等承诺默认 30 天；清理任务记录后仍保留到期前的键和响应摘要；到期语义可查询 |
| CO-05 | 拒绝伪完成 | HTTP 断开、取消已接纳、单次流结束、通知失败均不冒充业务完成 |

## 5. 完成标准

上述每项需求都必须映射到实施任务与自动验收。持久与并发保证使用真实本地 Postgres；重启使用独立进程；无需模型密钥的脚本模型验证运行语义。真实模型质量、线上容量与多机故障接管另行验收，不能由离线测试推断。

后续开始开发前需冻结：模块落点、首批部署模式和宿主认证接口。本文采用的建议值、Postgres 参考后端和单活动执行宿主均是设计提案，并非用户已确认的额外需求。
