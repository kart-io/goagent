# GoAgent 可组合编排能力需求文档

日期：2026-10-27

代码基线：`3bfeea70fcce35c3e925a295cc42546c1ec80b1b`  
配套：[实现方案](../plans/2026-10-27-composable-orchestration.md)、[多框架调研与复审](../../research/2026-10-27-framework-orchestration-review.md)

## 1. 目标与修订结论

为已有 Go 业务提供可复用、可计量、能解释失败的 Agent 编排。保留当前 Runnable、图状态和模型/工具持久日志，在边界增加能力，不引入另一套编排底座。

参考 Eino、LangGraph/LangChain、OpenAI Agents SDK、Google ADK 和 Temporal 后，本版调整为：工具化前补根级预算和资源生命周期；观察复用 OTel；持久引用先固定内容身份；数据流先原型；反射字段映射推迟。框架事实与本项目推导分列在调研文档中。

需求面向 GoAgent 使用者和维护者。本版是建议设计，不表示用户已确认所有拟新增 API、默认值或交付日期。

## 2. 当前能力与范围

| 方向 | 现有代码 | R2 范围 |
| --- | --- | --- |
| 工具化 | core.Runnable、FunctionTool、Dispatcher、Agent.AsRunnable | 显式编解码、独立会话、受控复合工具 |
| 流处理 | core.StreamRunnable、Generator、AdaptStream | 增量只读管道原型；不改图边调度 |
| 字段适配 | 类型化 Adapt、并行 Clone/Merge | 首轮继续使用 Go 函数；通用反射映射为候选 |
| 观察 | StreamEvent、observability 的 OTel 与指标 | 统一关联和只读导出；复用 OTel 身份 |
| 上下文 | 内存卸载、分页、历史摘要 | 内部组件抽取、不可变引用、有限策略扩展 |
| 成本与恢复 | 单 Agent MaxIterations、TokenUsage、durable.Do | 父子共享请求准入及回放计量；明确不透明工具恢复限制 |

Go 版本保持 1.25.0；不新增 Eino/LangGraph/ADK/Temporal 运行依赖；不向 core.Runnable 添加必需方法；旧 Pipe、Graph、Adapt/AdaptStream 的默认语义不变。持久图仍以合法最终结果推进状态，中间数据与观察事件不提交业务状态。

## 4. 功能需求

### FR-01 跨阶段增量处理，P1 原型

1. 以类型化 Source、Map、增量 Fold 验证只读跨阶段处理，作为一个整体 Runnable 节点接入旧图。不首发 Reader/Frame、Collect/Transform 四范式和自动流复制。
2. 数据、展示事件、最终快照分开。Source 每次调用数据回调都代表一个有效值，包括 0、false、空字符串或 nil；不能猜测中间 StreamChunk.Data 是否有值。
3. Source 返回 nil 才代表成功；每个增量经 Fold 聚合一次。只在 Source、变换、Fold、预览均成功后提交一个最终快照；先前展示的内容仍是暂态。
4. 首版同步回调形成背压，不额外创建队列；输出到旧 StreamRunnable 时沿用其缓冲与取消。适配已有异步模型时必须有独立可取消 context，并明确 join/清理责任。
5. 默认最多 1024 个数据项；输入大小由业务提供 Size 函数计量，缺省不宣称内存字节受限。无界字符串追加不会因帧数上限自动变为内存有界。
6. 提前退出、变换或输出错误取消上游；协作式生产者必须退出。不能强制终止不响应 context 的 Go 函数。
7. 原型只接收显式 source，不泛化猜测旧 channel/Generator 的终态。副作用节点放在聚合终态之后，持久图恢复重跑整个管道节点。

验收：屏障阻塞 Source 完成前下游已收到首个转换值；最终内容不重复；Source 先发数据后失败不提交终态；消费者取消不泄漏合作式任务。原型通过正确性、取消和一个业务首帧收益演示后，再评审是否发布稳定 API。

### FR-02 受控 Runnable 工具化，P0

1. 以显式 Name/Description/对象 Schema/Version、Decode 和 Encode 将 Runnable 包为 Tool；Graph 的普通 Compile 产物和 Agent.AsRunnable 共用适配器。
2. Args 只承载模型参数；CallerID、CallID、ExecutionKey、权限、预算和 deadline 由宿主 context 提供。身份传递不等于模型获得身份数据，子工具仍逐次授权。
3. 使用 Dispatcher.Tools 获得调用日志。适配器本身不宣称 DurableCallTool。新版本描述进入意图，旧普通工具意图 JSON 与哈希保持兼容。
4. 有状态子 Agent 每次调用使用独立会话与记忆命名空间；factory 不只创建新指针，还负责唯一 SessionID。默认不复制父对话，父授权、预算和取消显式继承。
5. factory 返回 owned 执行对象及清理函数；成功、失败、取消均清理，主错误与清理错误合并；不得关闭宿主共享资源。清理失败不缓存工具成功。
6. 子 Agent 使用独立 Dispatcher；同一执行链重入同实例在排队前失败。各层并发上限与根请求预算独立。深度默认最多 8；父 deadline 不能被子工具延长，长任务超时由宿主配置。
7. 首版是“不透明复合调用”：有日志时最多实际尝试一次；completed 直接复用；pending/failed 返回需要宿主处理，不进入 factory。没有日志时不承诺跨进程去重。
8. 一次尝试不代表子流程可续跑。即使子模型已保存成功，父包装未完成时也不自动进入子 Agent。审批型 DurableGraph、Handoff、独立持久子工作流与任意嵌套恢复不在本版范围；等待不能编码为成功。
9. 暴露模型型子工具必须先接入 FR-06；自定义 Runnable 若直接绕过受控模型入口，宿主不能宣称全链路预算得到执行。

验收：普通规则图工具、并发独立子会话、相同 CallID 成功回放、版本拒绝、8/9 层边界、同实例重入、父取消、factory 各路径清理、pending 包装停止，及根预算用例均通过。

### FR-03 类型化字段适配，首轮示例；通用映射 P2

首轮使用现有 Adapt/AdaptStream 和显式 Go 输入输出函数；并行来源先 Clone/Merge，再转换到节点参数。保留编译期类型检查，不新增 string 字段路径、隐式转换或全局 reducer。

交付订单查询、并行诊断两个示例，验证零值与 nil 的业务处理、映射错误不调用节点、来源状态不被修改。只有至少两个独立业务场景显示大量重复适配且路径配置确有收益，才启动通用映射的专项设计；动态类型、默认值、nil 路径、引用别名与持久版本届时一并评审。

首轮示例完成不等于通用字段映射能力完成。

### FR-04 可观察性与只读调试，P0 最小集 / P1 展示

1. 导出版本化拓扑：节点、边、候选分支、并行分支，稳定排序，不包含闭包。
2. 复用已有 OTel TraceID/SpanID/父子 context，补节点、Agent、工具、模型回合的生命周期。RunID/VisitID/EventID 用于业务关联与排序，不替代 trace 或幂等键。
3. 每次恢复可使用新的 OTel span，通过稳定 OperationKey、RunID 和 Replayed 关联历史；不持久保存已结束的 span 并在重启后复活。OTel 未启用时仍可导出运行事件，TraceID 允许为空。
4. 累计历史用量和本次新增请求分开，工具回放不生成“新增计费请求”事件。观察记录不提供恢复依据，不是账本。
5. JSONL 默认记录结构、状态、耗时、错误类别和 replay 标记，不记录 Args、提示词、原生续接字段或完整异常字符串。正文仅在宿主显式允许字段且脱敏后导出。
6. 内建记录器异步有界：队列 64、最多 10,000 个事件；丢弃数量可见，主执行不等待磁盘。用户自定义同步 Observer 的阻塞行为由宿主承担，框架不承诺任意回调都非阻塞。
7. 首轮仅只读导出；离线 HTML 查看后置。移除通用 Debugger.Run。模拟节点使用明确注入 fake 工具/服务的示例，Effect=false 标签不能证明没有外部副作用。

验收：OTel 父子关系、循环访问区分、恢复关联、默认无敏感正文、记录器失败不改变结果、队列饱和可观察。后续 HTML 必须转义不可信内容。

### FR-05 上下文组件与不可变引用，P0B 持久引用 / P1 扩展

1. 先拆分内部卸载、分页、摘要预算和最终回合恢复职责，保持 WithContextPolicy 行为；之后才开放窄消息变换及可选工具/统计接口。请求级 Middleware 不被替换。
2. Policy descriptor 包含 ID、Version、规范化 ConfigHash，按顺序进入模型意图。相同版本不同阈值、分页设置、排除工具或 Store 命名空间不能复用旧意图。
3. 不允许策略直接多次调用模型，摘要仍走 Builder 统一模型入口并计入局部和根预算。不可篡改 system、身份、原生续接字段和 tool_call/result 关联；不能仅靠浅复制做校验。
4. 引用区分运行作用域、逻辑结果 ID、内容 SHA256 和格式版本。稳定 key 采用结构化编码派生，不直接拼接未转义组件，避免 ID 含斜线造成碰撞。
5. PutIfAbsent：相同 key/摘要重复写入成功，不同内容冲突；不允许覆盖。引用先保存，再持久保存含引用的模型请求。恢复按固定摘要读取，禁止 latest，Get 校验作用域和摘要。
6. 存储可先提供内存实现与 durable.Store 适配。新引用快照带独立版本，不改变既有 OperationRecord。预算与引用都不能复用已被图持有的同一锁 ID。
7. 持久卸载和分页首轮支持；持久摘要、不具备恢复能力的策略在首次请求前拒绝。动态分页工具仍走统一授权、CallID 与日志入口。
8. 引用保留至宿主清理运行；不自动 TTL 删除活跃运行数据。摘要有语义损失风险，结构校验不等于保证证据完整；业务需验证最终答案。
9. 字符限制继续明确为 Unicode 字符，不伪称 Token 硬上限；不承诺进程内存下降或旧检查点正文被自动删除。

验收：旧策略兼容、配置变化拒绝、固定内容冲突、跨运行拒绝、保存失败零后续模型请求、两个崩溃窗口、重启分页可读与最后回合恢复原文。

### FR-06 父子共享预算与计量，P0 新增

1. 模型型工具发布前配置根级 MaxModelRequests，值须显式大于 0；局部 MaxIterations 仍生效。预算是父、子、摘要的共同准入额度，不是各子任务重新获得一份额度。
2. 在真实模型请求前、完成回放查找后准入；并发原子预留，不超过根额度。回放不扣新额度；预留后崩溃而发送状态未知时保守占用，不自动退款或再次发送。
3. 非持久使用内存计数；持久模式要求宿主提供同 Store、稳定 root key 和配置版本的独立预算账本。重启不重置额度，额度/版本改变拒绝恢复。账本保存失败时不请求模型。
   有 journal 的新受控路径绑定内存 Controller 时必须在首次请求前拒绝。Controller 模式由框架检查，Store 与 root scope 的实际归属由宿主在同一运行构造中绑定并校验，不声称能从任意 Store 接口证明物理后端相同。
4. 此准入只覆盖接入 Builder 统一调用路径的模型调用；外部 SDK 内部重试、自定义 Runnable 的隐藏请求不自动受控。首轮受控路径禁用隐式模型重试。
5. 通过稳定模型操作键登记用量，父子仅汇总一次，回放登记幂等；未知用量保持未知。分别报告准入预留数、累计已知用量和本次执行新增请求，不能将预留数叫作实际计费请求数。
   失败模型操作也登记已取得用量；completed 回放可补登记，failed/pending 只读已有证据补齐，不以补计量为由再次请求模型。
6. 请求额度可硬性控制；已知 Token 阈值只能作为后续停止条件，不承诺实时美元或 Token 硬上限。最后一次请求与未知响应可能超出已知统计。
7. 旧未启用组合功能的单 Agent 路径保持原行为；新模型型工具缺根预算时在调用子模型前失败。

验收：父请求 1 次、两个并发子任务竞争根剩余 1 次时最多再发送 1 次；额度 2 的第三次准入失败；completed 回放不增加请求；预留后进程退出额度仍占用；预算保存失败零请求；用量缺失和重复回放不虚增。

## 5. 非功能与兼容

| 编号 | 要求 | 验收 |
| --- | --- | --- |
| NFR-01 | 原必需接口、无功能配置的意图哈希和执行入口不变 | 旧 Runnable/日志 fixture 回归 |
| NFR-02 | 新并发路径响应 context，清理合作式任务 | race、屏障与故障测试 |
| NFR-03 | 保存、解锁、清理或非法终态错误不得伪装成功 | 错误链与调用次数断言 |
| NFR-04 | 不新增外部编排或前端运行依赖 | go.mod、导入规则检查 |
| NFR-05 | 新配置版本明确，旧运行不被静默重解释 | 版本/意图/引用与预算冲突测试 |
| NFR-06 | 开销有同机基准证据 | 前后重复 benchmark，记录 ns/op、B/op、allocs/op；显著回退需解释，不预设未经测量的 5% SLA |

## 6. 修订交付顺序

| 阶段 | 交付 | 依赖与准入 |
| --- | --- | --- |
| M0 | FR-06 根预算、计量语义；FR-04 最小事件/OTel 关联 | 模型型工具发布前置 |
| M1 | FR-02 普通图与独立子 Agent 工具化；FR-03 两个类型化示例 | 模型型子工具依赖 M0；纯函数图可先单独测试 |
| M2 | FR-05 内部拆分、不可变引用、持久卸载与有限扩展 | 摘要走 M0 预算，持久摘要继续拒绝 |
| M3 | FR-01 只读流原型；FR-04 离线只读报告 | 流 API 经原型评审后才稳定，不阻塞 M1/M2 |
| 候选 | 通用反射映射、四范式、嵌套恢复/审批、分类重试、持久摘要 | 各自业务证据与故障专项方案 |

首轮完成定义：M0–M2 的实现/回归/离线示例齐备，M3 形成可运行原型及采用/推迟结论；不将候选功能算作已实现。订单闭环覆盖模型型工具、独立会话、父子预算、固定版本引用和只读观察；流原型单独验证，不强行与持久运行共用帧协议。

## 7. 不在首轮范围

跨主机调度、租约/fencing、外部 exactly-once、自动补偿、任意调用栈恢复、持久 Token 回放、异构字段 DAG、远程节点执行、Handoff、脱离父生命周期的后台 Agent，以及任意嵌套审批。需要这些能力时优先评估成熟工作流系统的适配，不把 FileStore 包装成分布式调度器。
