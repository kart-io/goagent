# 存储所有权、命名空间与缓存契约

`memory.Store` 与 `InMemoryLangGraphStore` 在写入时保存独立快照，`Get`、`Search` 和每个 Watch 订阅者取得独立副本。修改输入、读取结果或成功 Update 回调保留的对象都不会修改已保存记录。调用期间不得并发修改正在传入的对象；Update 回调不能重入同一存储。回调返回错误或发生 panic 时不发布记录、版本、时间戳或事件；panic 继续传递给调用方。

快照保留具体 Go 类型，支持命名 map/slice、`[]byte`、指针、数组、导出结构字段及普通图遍历中遇到的环与重复对象引用；`time.Time` 按不可变值复制。对同一可寻址结构体或数组，预登记内联字段地址，因此 `Alias = &record.Value`、指向嵌套内联结构体及数组元素的别名会指向副本内相应字段。跨独立堆对象的内部字段地址关系不作通用保证，例如一个对象中的指针指向另一个独立指针对象的某个字段，需要业务快照协议维护自身不变量。切片只复制可见长度，不保留容量，也不承诺不同切片视图的重叠关系或跨视图内部地址关系。map 的指针键也会复制，读取后应使用副本中的键。

非空函数、通道、`unsafe.Pointer`、包含可变私有字段的类型以及 `sync`/`sync/atomic` 同步对象会导致写入失败，不会回退到共享引用。业务类型可实现结构协议 `CloneSnapshot() (any, error)`，返回同类型的独立副本；协议实现负责自身不透明状态、内部环、重复调用及错误处理。不要复制锁本身，也不要在协议内把包含自身的图直接递归传给新的快照调用。外部包无需导入 internal 接口即可实现该方法。

`CloneSnapshot` 必须是纯复制：不得重入存储、缓存或状态操作，不得获取可能与调用方形成锁反转的锁。普通内存 Put 在锁外复制输入，Get/Search 在锁内选出不可变记录后锁外复制；Update、Watch通知准备及缓存协调仍可能在锁内调用协议。协议返回错误或panic不能遗留自己持有的资源。框架不会为用户协议创建额外调度器，也不承诺重入安全。

存储公开边界将快照失败分类为 `STORE_SERIALIZATION`，通过 Cause 保留底层错误，可用 `errors.Is` 检查；空更新结果分类为 `INVALID_INPUT`，metadata后端能力不足为 `INVALID_CONFIG`，关闭缓存为 `STORE_CONNECTION`。Update回调返回的业务错误继续向调用方传递。

旧代码若通过 `Get(...).Metadata[...] = ...` 修改元数据，应改用 `memory.Store.PutWithMetadata(ctx, namespace, key, value, metadata)`。它在一次写入内合并元数据，更新同一 key 时保留未覆盖字段、保持 Created，并原子替换索引。`Put` 保留既有元数据；结构化元数据使用完整相等扫描，标量使用索引。`decorator.WithMetadata` 使用可选的 `store.MetadataWriter` 接口一次提交，支持叠加装饰器；不支持该接口的后端会在写入前报错。装饰器构造时保存配置快照，不可快照配置在首次 Put 时返回错误。

两个内存存储统一使用长度前缀编码命名空间：`["a:b"]` 为 `3:a:b`，`["a","b"]` 为 `1:a1:b`；空数组和 nil 都是根空间，`[""]` 是独立空间。所有公开存取、查询、清理和 Watch 路径均使用同一编码。`memory.Store.Namespaces()` 现在返回该编码，旧的 `/users` 形式变为 `5:users`。两者都是易失内存实现，无磁盘数据迁移；使用 Namespaces 输出做解析或对账的宿主需要调整，不能把旧的分隔符拼接结果映射为唯一空间。

Watch 是有缓冲、非阻塞的尽力通知，缓冲满仍会丢事件；它不是持久事件日志。取消与 Close 在同一锁下删除注册项并唯一关闭通道，Close 会注销取消回调；Background context 不占用永久等待 goroutine。

`StoreWithCache` 缓存完整 StoreValue，包括后端 Version、Timestamp、Metadata 与业务 TTL。配置 ttl 为正时另设本地淘汰期限；ttl<=0 表示不额外限制缓存寿命，业务 TTL 始终按原 Timestamp 判断。后端成功写入后先失效，再尽力读取完整条目预热；预热失败不会把已提交写入误报为失败。冷缓存删除或更新也保持后端成功结果。包装器内的 Get 与写操作串行，避免冷读与失效交错发布旧值。这个锁会串行化该实例的后端 I/O；大规模并发场景需要衡量吞吐。

缓存不会监听直接写入后端或其他包装器的修改，可能在配置期限内返回旧值；宿主需自行限制这种用法或选择较短 ttl。Search、List、Watch 继续使用后端能力。Close 仍同时关闭包装器缓存与后端，注入后端的生命周期由现有接口约定负责。
